接住 — 專案架構與資料庫說明

最後更新：2026-07-26 ｜ 分支：feat/benefit-source-discovery

這個專案在做什麼？

「接住」是一個福利導航 Agent。當使用者描述自己遇到的人生事件（例如：親人過世）， 系統會自動找出可能適用的政府補助、告訴使用者符不符合資格、需要準備什麼文件、去哪裡辦。

關鍵原則：AI 不能自己決定你符不符合資格。AI 負責理解你的話、找資料；規則引擎負責用確定的邏輯判斷資格。

資料庫在哪裡？

只有一個 SQLite 檔案

data/local/government_oid.db

這個檔案：

  • 不進 Git（被 .gitignore 排除）
  • 可以用指令從頭重建
  • 只存在你的電腦上，用來開發和 demo
  • 不存使用者個資、不存密碼

Rule Engine 怎麼運作？

概念

Rule Engine 是一段固定的程式碼，不管有 5 筆或 10 萬筆方案，都用同一套邏輯。

它做的事就是：讀取 program_rule_fields 裡的值，跟使用者提供的屬性比對。

例子

使用者說：「骨灰從臺北靈骨塔遷出，已完成樹葬，30 天前領回」

系統抽出屬性：

屬性值
remains_typeash（骨灰）
eco_burial_completedtrue
days_since_remains_pickup30
jurisdictionTPE（臺北市）

Rule Engine 拿這些屬性去比對臺北市鼓勵金的規則欄位：

  • eligible_remains_types = ["ash", "bone"] → ash 有在裡面 ✓
  • eco_burial_required = true → 使用者已完成 ✓
  • application_deadline_days = 60 → 30 天 < 60 天 ✓
  • amount_conditions: remains_type=ash → 10,000 元

結果：eligible，金額 10,000 元

目前有的結構化欄位種類

欄位名稱類型說明
min_amountinteger最低金額
max_amountinteger最高金額
amount_conditionsjson金額分級條件（例如骨灰1萬、骨骸2萬）
application_deadline_daysinteger申請期限（天數）
post_completion_deadline_daysinteger完成後幾天內要送件
deadline_starts_fromtext期限從什麼事件開始算
requires_city_registrationboolean是否限設籍該縣市
eligible_remains_typesjson適用的骨灰骸類型
eligible_deceased_statusesjson亡者需符合的身分（低收等）
eco_burial_requiredboolean是否需完成環保葬
eco_burial_location_restrictedboolean環保葬地點是否限本市
source_facility_requiredjson骨灰骸必須從哪些設施遷出
application_period_startdate受理開始日期
application_period_enddate受理截止日期
application_start_datedate方案實施日期
budget_limitedboolean是否預算用罄即停止
service_items_countinteger免費服務項目數量
fee_reduction_for_unqualifiedboolean不符資格者是否可減半收費

這些欄位不是固定的。你可以在 Review UI 上隨時新增新的欄位種類。

一筆補助方案的生命週期

發現候選連結 ↓ 人工核准下載 (death_benefit_first_batch.v0.1.json) ↓ 下載官方頁面 → 存入 source_documents ↓ 解析 HTML → 產生候選 JSON (extracted_candidates.v0.1.json) ↓ 載入 DB → benefit_programs (status = candidate) ↓ AI 補齊缺少欄位（從已接來源搜尋） ↓ 人工在 Review UI 檢查 ├── 資料正確 → 填入結構化規則欄位 → 標為 verified └── 資料不足 → 標記需人工查 or 繼續搜尋 ↓ verified 的方案 → Rule Engine 可以用來判斷使用者資格

如何從零重建整個資料庫

Clone 專案後，在 repository 根目錄依序執行：

  1. python3 scripts/import_government_oid.py — 匯入 OID
  2. python3 scripts/init_benefit_catalog.py — 建 catalog 表
  3. python3 scripts/sync_benefit_sources.py — 同步入口頁
  4. python3 scripts/fetch_reviewed_benefit_pages.py — 下載核准頁面
  5. python3 scripts/extract_benefit_candidates.py — 解析候選
  6. python3 scripts/load_candidates_to_db.py — 寫入 DB

啟動審查介面：

backend/.venv/bin/python3 scripts/review_server.py

然後開 http://localhost:8100
